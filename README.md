# ميزان — Financial Workspace

واجهة React + TypeScript للأقسام الثلاثة: **التحليل المالي، القوائم المالية، والتسويات البنكية**. أضيف خادم Node محلي وأرشيف نسخ مالية في Neon Postgres؛ راجع [إعداد Neon وحدود الحفظ](NEON-SETUP.md).

أضيف أيضًا نموذج قاعدة بيانات SRS: **107 جداول وظيفية** للمؤسسات والصلاحيات والاستيراد والتقارير والتسويات والاعتماد والفوترة والخصوصية والتكاملات. راجع [التغطية والقيود](docs/DATABASE-SRS.md) و[قاموس الحقول](docs/DATABASE-FIELDS.md). إنشاء الجداول لا يربط جميع الواجهات بها تلقائيًا؛ العرض المالي التجريبي يحتفظ بأرشيف النسخ المستقل المتصل بـNeon.

بدأ الخادم الحقيقي: دخول وتسجيل وMFA، ومساحات عمل ومنشآت وفترات محفوظة وصلاحيات خادمية وسجل تدقيق. افتح `/#/workspace`؛ العرض المالي التجريبي مستقل عنه. راجع [نطاق Backend v1 وطريقة تشغيله](docs/BACKEND-V1.md).

أُضيف مسار مالي متصل داخل مساحة العمل: استيراد ميزان مراجعة CSV مصنف، حفظ المصدر مشفرًا في تخزين Neon خاص، وحفظ صفوف الحسابات وثلاث مسودات خادمية (الدخل، المركز المالي، التحليل) مع تتبع المصادر والإصدارات. تظل المصادر في الحجر والنتائج غير معتمدة حتى فحص الملفات ومراجعة الاكتمال. راجع [النطاق والقيود والاختبارات](docs/BACKEND-FINANCIAL-V2.md).

أُضيفت مسودات التسوية البنكية المتصلة: حساب بنكي بمعرّف مشفر، استيراد كشف البنك ودفتر البنك مع فحص الأرصدة والإشارات، وحفظ الحركات واقتراحات المطابقة والالتباس وأدلة الصفوف. تُحفظ نتائج الاستيراد أولًا كاقتراحات غير مؤكدة دون تخصيصات أو قيود. راجع [نطاق التسويات البنكية والاختبارات](docs/BACKEND-BANK-V3.md).

يمكن الآن تأكيد الاقتراح الفريد واحدًا لواحد وإلغاؤه بسبب موثق، مع تخصيص الحركة وعكسه مرة واحدة وحفظ سجل القرارات والمبالغ المتبقية. تظل التسوية مسودة غير معتمدة، وتُرفض الحالات الملتبسة أو القرارات القديمة. راجع [قرارات المطابقة وضوابطها](docs/BACKEND-MATCHES-V4.md).

## التشغيل

تتيح لوحة المصادر المفحوصة معاينة CSV وXLSX وربط الأعمدة مع الحفاظ على دقة الأرقام. يتطلب المسار فحصًا ناجحًا وصورة معالجة محلية معزولة. [تشغيل المعاينة وحدود الاختبار](docs/BACKEND-IMPORT-PARSER.md)

أُضيف رفع المصادر المشفرة ومتابعة مهام الفحص وإلغاؤها وإعادة محاولتها، مع دور عامل مستقل ورموز حجز تمنع النتائج المتأخرة. الفاحص الحقيقي غير مفعّل بعد؛ الملفات تبقى محجورة عند غيابه. راجع [خدمات المصادر والمهام وإعداد الفاحص](docs/BACKEND-SOURCE-JOBS.md).

تتضمن التسويات المتصلة الآن بنود فروقات موثقة وأرصدة معدّلة وفارقًا متبقيًا وتغطية مطابقة بالعدد والقيمة، مع قيود مقترحة غير مرحلة وضوابط تصفية وترحيل. راجع [العقود والاختبارات والقيود المتبقية](docs/BACKEND-RECONCILING-ITEMS.md).

أُضيفت المطابقات الجزئية والمجمعة، ودعوات بصلاحيات محددة، وإلغاء الصلاحيات وإعادة تفعيل العضوية دون استعادة صلاحياتها القديمة، ومسار مراجعة مستقل مع السحب وطلب التعديل والرفض. يمنع الخادم اعتماد المصادر المحجورة أو تعديل فترات مغلقة. راجع [خدمات الإدارة والمراجعة وأدلة الاختبار](docs/BACKEND-REVIEW.md) و[سجل الإكمال المتبقي](docs/BACKEND-COMPLETION.md). أرشيف العرض التجريبي القديم غير مفعّل افتراضيًا؛ افتح `/#/workspace` للبيانات الفعلية.

```powershell
npm install
neon deploy
npm run db:migrate
npm run backend:setup
npm run dev
```

افتح الرابط الذي يطبعه Vite ثم `/#/app/overview`. الخادم الموجود أثناء التنفيذ متاح على `http://localhost:5174/`.

```powershell
npm run build
npm test
```

## تجربة المدخلات والمخرجات

1. افتح **مركز البيانات** ونزّل نموذج CSV. أعمدته: `accountCode,name,classification,signedDebitBalance`.
2. الأرصدة المدينة موجبة والدائنة سالبة. عاين الملف ثم انشره إذا كان الميزان متوازنًا. يتحدث التحليل وقائمتا الدخل والمركز المالي من الحسابات المستوردة.
3. افتح **التسويات البنكية** ثم **إعداد تسوية**. يمكن استخدام البيانات المرفقة أو إدخال ملفين CSV للبنك والدفاتر بأعمدة `date,description,reference,amount`، مع أرصدة الفترة. المبالغ بإشارة التدفق النقدي.
4. من **مساحة المطابقة** حدد الحركات وأكّد المطابقة. يدعم التخصيص الجزئي والمدفوعات السالبة، ويرفض تجاوز المبلغ المتاح.
5. من **كشف التسوية** راجع الرصيدين والفروق، وأضف تفسيرًا موثقًا عند الحاجة. القيود المقترحة لا تُرحّل إلى ميزان المراجعة.
6. أرسل الإصدار للمراجعة، واختر **عمر** من أدوات العرض التوضيحي أسفل الشاشة، ثم افتح المراجعة واعتمد الإصدار إن استوفى الشروط. لا يجوز للمعدّ اعتماد عمله. بعد الاعتماد يصبح الإصدار مقفلًا.

## الأدوار والسيناريوهات

أدوات العرض تختبر مايا (إعداد)، عمر (مراجعة)، لينا (اشتراك بلا نطاق مالي)، ونور (إدارة منشآت). تغيير المنشأة أو الفترة يعزل سياق العمل. استخدم «الحفظ والاسترجاع» لحفظ نسخة مالية يدويًا في Postgres ثم استرجاعها بعد إعادة التحميل. العمل غير المحفوظ وقرارات التسويات البنكية تظل في ذاكرة الجلسة.

## حدود النسخة

- CSV وXLSX يعملان محليًا؛ القالب الموحد متاح من التحليل ← المدخلات. ملفات XLS القديمة وPDF/OCR غير مدعومة.
- يوجد خادم محلي لمستخدم واحد وحفظ دائم لنسخ التحليل والقوائم والتخطيط. تتوفر مصادقة حقيقية وMFA وخدمات مساحات العمل والمنشآت والفترات. لا توجد خدمة عامة منشورة أو إرسال بريد أو دفع أو ربط بنكي خارجي أو ترحيل محاسبي. قرارات التسويات والاعتماد لا يشملها الحفظ الحالي.
- صفحات الأعضاء والسياسات والخصوصية والتكاملات تميز العرض والمسودات والطلبات المحلية عن الإجراءات الإنتاجية.
- قائمة التدفقات النقدية والتغيرات في حقوق الملكية ومؤشرات تفتقد مدخلاتها ليست مخرجات مختلقة.
- صلاحيات الواجهة وطبقة البيانات المحلية لعرض التدفقات؛ تطبيقها الإنتاجي يحتاج إلى خادم.

## التصميم والمراجع

المراجع الأصلية محفوظة: `DESIGN-SYSTEM.md` و`DESIGN-MASTER.md` وملفات tokens وBRD وSRS. استُخدمت مهارة **UI UX Pro Max** المثبتة ضمن حزمة البرومبتات السابقة على الجهاز، دون استبدال نظام الألوان أو ترقية المكتبات. اسم **ميزان / Mizan** هوية واجهة مقترحة وقابلة للتعديل.

تدعم الواجهة العربية RTL والإنجليزية LTR والمظهرين الفاتح والداكن والكثافة والأرقام. تفاصيل الفحص والصور موجودة في `verification/` و`FRONTEND-DELIVERY.md`. الإضافات الأحدث وطريقة استخدام Excel والموازنة والسيناريوهات والتقرير موثقة في [FINANCIAL-SUITE.md](FINANCIAL-SUITE.md).
